# Feature Goals — async-config-loader

## Goal 1: Convert config loader to async file I/O

- **Goal:** `src/config/loader.js` uses synchronous filesystem I/O (`readFileSync`, `writeFileSync`) inside functions called from async contexts. Per AGENTS.md §1.1, blocking operations inside async functions are forbidden. `loadConfig()` uses `readFileSync(CONFIG_PATH, "utf-8")` and `saveConfig()` uses `writeFileSync(CONFIG_PATH, yamlContent)`. Both block the event loop.
- **Scope:** Convert `loadConfig()`, `saveConfig()`, and `setConfigValue()` in `src/config/loader.js` to async functions using `node:fs/promises`. Update all callers to `await` them.
- **Key Requirements:**
  1. `loadConfig()` uses `readFile` and `access` from `node:fs/promises` instead of `readFileSync`/`existsSync`.
  2. `saveConfig()` uses `writeFile` and `mkdir` from `node:fs/promises` instead of `writeFileSync`/`mkdirSync`.
  3. `setConfigValue()` becomes async and `await`s `saveConfig()`.
  4. All callers across `src/` and `index.js` `await` the async functions.
- **Acceptance Criteria:** No `readFileSync`/`writeFileSync`/`existsSync`/`mkdirSync` remain in `src/config/loader.js`. All callers updated. Tests and lint pass.
- **Dependencies:** `src/config/loader.js`, `index.js`, all caller modules in `src/`, affected tests.
- **Risks / Edge Cases:** Module-top-level callers (`const cwd = loadConfig().cwd`) cannot `await` at top level; must be refactored to lazy accessors or moved into async functions. `index.js` startup ordering. Tests importing modules that call `loadConfig()` at top level.

## Goal 2: Preserve existing behavior

- **Goal:** The conversion must not change config loading semantics — cache, env-var resolution, schema validation, and `_setResolvedConfig()` wiring must be preserved.
- **Scope:** Keep `cachedConfig` module-level cache, `syncEnv`/`_resolveEnvRecursively` pipeline, and `validateConfig` unchanged.
- **Key Requirements:**
  1. `cachedConfig` cache preserved (subsequent calls return same object).
  2. `_setResolvedConfig(config)` still called after load.
  3. Env-var resolution and schema validation unchanged.
- **Acceptance Criteria:** `loadConfig()` returns the same validated config object as before; `getConfig` tool returns the same structure.
- **Dependencies:** `src/config/loader.js`, `src/config/config.js`.
- **Risks / Edge Cases:** None beyond Goal 1.
