# Test Patterns — async-config-loader

## Testing framework
- `node --test` (built-in) with `describe`/`it` from `node:test`.
- `assert` from `node:assert` (strict mode via `assert.strictEqual`, `assert.deepStrictEqual`).
- Tests use `async` functions and `await import(...)` for dynamic module loading.

## Related tests

### `tests/unit/tools/getConfig.test.js`
- Tests the `getConfig` tool which calls `loadConfig()`.
- Uses `await getConfig.invoke({})` — the tool is async.
- Tests: successful config retrieval, JSON formatting, error propagation, input validation, metadata.
- **Impact:** `getConfigImpl` in `src/tools/config/index.js` calls `loadConfig()` synchronously. After conversion, it must `await loadConfig()`. The test already `await`s `getConfig.invoke()`, so it should continue to pass.

### `tests/integration/syncEnv.test.js`
- Tests `syncEnv` and `KNOWN_SECTIONS` from `src/config/loader.js`.
- Imports `syncEnv, KNOWN_SECTIONS` directly (not `loadConfig`).
- **Impact:** No direct `loadConfig()` call at module top-level. The test imports `syncEnv`/`KNOWN_SECTIONS` which are not affected by the async conversion. Should continue to pass.

## Conventions
- Tests mirror `src/` structure in `tests/unit/`.
- Mock external services — no real API calls.
- Each public function/class needs at least one test.
- Test filenames use `.test.js` extension.
