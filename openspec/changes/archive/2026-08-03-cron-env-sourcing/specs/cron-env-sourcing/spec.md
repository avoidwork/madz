## ADDED Requirements

### Requirement: Madz writes .env.cron on startup
The system SHALL write a `.env.cron` file to the project working directory on application startup, containing all required environment variables in `export KEY=VALUE` format. The file SHALL be written before any crontab synchronization occurs.

#### Scenario: Env file is written at startup
- **WHEN** the application starts with schedules enabled
- **THEN** a `.env.cron` file exists at `{cwd}/.env.cron` containing exported environment variables

#### Scenario: Env file contains required variables
- **WHEN** the `.env.cron` file is written
- **THEN** it includes `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `NODE_OPTIONS`, and `TZ` if present in `process.env`

#### Scenario: Env file is written before crontab sync
- **WHEN** the application starts and `Cron.sync()` is called
- **THEN** `.env.cron` exists before any crontab entries are written

### Requirement: Crontab commands source the env file
The system SHALL prepend `. /{cwd}/.env.cron 2>/dev/null || true && ` to every crontab command generated by `prepareCrontabCommand()`.

#### Scenario: prepareCrontabCommand prepends sourcing
- **WHEN** `prepareCrontabCommand("cd /path && node index.js")` is called
- **THEN** the result is `. /{cwd}/.env.cron 2>/dev/null || true && cd /path && node index.js`

#### Scenario: Sourcing prefix is added to all entries
- **WHEN** `Cron.add()`, `Cron.install()`, or `Cron.sync()` writes crontab entries
- **THEN** every command is prefixed with the env sourcing statement

#### Scenario: Sourcing failure does not abort the job
- **WHEN** `.env.cron` is missing and a cron job runs
- **THEN** the job still executes (the `|| true` ensures no abort)

### Requirement: Crontab entries use dot command for sourcing
The system SHALL use the dot (`.`) command to source the env file, not `source` or `env`.

#### Scenario: Dot command is used for sourcing
- **WHEN** a crontab entry is generated
- **THEN** the prefix uses `. /{cwd}/.env.cron` (POSIX-compliant dot command)
